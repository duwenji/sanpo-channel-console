## 目的・背景

[ADR-001](../adr/ADR-001-aws-architecture.md) T-6 の 3 番目のうち、最初の部分（3a）。配信元が登録し、鍵を紐づけ、チャンネル ID を登録し、パッケージに署名して申請（アップロード）できるようにする。届いたパッケージの機械審査は 3b、運用者の審査は 3c、鍵の移し替えとメールの通知は 3d で作る。

## 方針・決定事項

### 決定事項（開発者の回答、2026-10-04）

| No. | 論点 | 決定 |
|---|---|---|
| P-1 | 実装の順番 3 の分け方 | 3a（配信元）→ 3b（機械審査）→ 3c（審査）→ 3d（鍵の移し替え・通知）の 4 つの PR |
| P-2 | 配信元の鍵の作成と署名 | 画面の中（ブラウザの WebCrypto の Ed25519）。秘密鍵は合言葉で暗号化したファイルとして配信元が保存し、サーバーに送らない |

### 今回の API

| 操作 | パス |
|---|---|
| 登録・確認・変更・退会 | `POST`・`GET`・`PATCH`・`DELETE /api/publisher` |
| 鍵の紐づけ | `POST /api/publisher/keys/challenge`、`POST`・`GET /api/publisher/keys` |
| チャンネル | `POST`・`GET /api/channels`、`GET /api/channels/{channelId}`（自分のもの。運用者はすべて） |
| 申請 | `POST`・`GET /api/channels/{channelId}/submissions`、`GET …/{submissionId}`、`POST …/withdraw` |

### 実装上の判断

| No. | 判断 | 理由 |
|---|---|---|
| J-1 | トランザクションの条件のどれが落ちたかを見て、`already_registered`・`account_id_taken`・`channel_id_taken`・`limit_reached`・`quota_exceeded`・`pending_submission_exists`・`challenge_invalid` に分ける | API-001 のエラー表どおり、配信元に原因を示す |
| J-2 | 鍵の紐づけは、一度きりの文字列の削除・アカウントIDの予約・鍵・配信元の更新・操作の記録を 1 つのトランザクションで行う。一度きりの文字列は 10 分 | DM-001 M-7・DV-02。使い回しを防ぐ |
| J-3 | 申請の開始は、1 日の数（日本時間）・チャンネルの審査待ち・申請・操作の記録を 1 つのトランザクションで行う | DM-001 M-2・DV-03・DV-04 |
| J-4 | アップロードが 1 時間届かない申請は、次の申請の開始のときに `expired` にしてチャンネルを空ける | 届かなかった申請でチャンネルが塞がらないように |
| J-5 | ほかの配信元のチャンネル・申請は 404（存在を明かさない）。運用者はすべて見られる | API-001「権限とデータの見え方」 |
| J-6 | 退会は、公開中のチャンネルの取り下げ（理由「配信元が退会したため」）、審査待ちの申請の取り消し、表示名・連絡先の削除、Cognito のユーザーの削除。操作の記録、アカウントIDの予約、チャンネル ID は残す | API-001 C-4、DM-001 M-15 |
| J-7 | 受付用の S3 は非公開。署名付き POST（15 分）で、大きさ（パッケージ 2MB・アイコン 100KB）と Content-Type を S3 が強制する。CORS はすべての送り元を認める（署名付きのポリシーがなければ上げられない。送り元を画面に限ると CloudFormation の依存が一周する） | API-001 C-10 |
| J-8 | 受付用の S3 の `archive/` は 90 日、`intake/` は 30 日で消す（結果の出なかった申請の分） | DM-001 M-4 |
| J-9 | 鍵のファイルは、秘密鍵（PKCS#8）を PBKDF2（SHA-256、60 万回）+ AES-GCM で暗号化した JSON。開くときに、中の秘密鍵と公開鍵が組になっているかを確かめる。合言葉は 12 文字以上 | ファイルが流出しても使えないように。公開鍵だけ差し替えたファイルを拒む |
| J-10 | 画面での署名は、ZIP を展開し、`signature.json` 以外の全ファイルの SHA-256 に署名して `signature.json` を足し、ZIP にし直す。前の `signature.json` は捨てる。署名の前に、`channel.json` の `id`・`version`・`publisher` を確かめる | API-003 F-6。アカウントIDの計算はサーバー・station-format と同じ値（テストで確認） |

## 検証結果

| 項目 | 結果 |
|---|---|
| テスト | 82 件合格。配信元の API の 13 件（DynamoDB Local）: 登録の重複、鍵の紐づけ（別の鍵の署名・期限切れ・使い回し・アカウントIDの重複）、チャンネル（未紐づけ・ID の重複・上限 5）、他人のチャンネルが 404、申請（署名付き POST の大きさと種類、審査待ち 1 つ、1 時間で解放、1 日の上限と日本時間での切り替え、取り消し）、停止中の拒否、退会。画面の暗号の 6 件（鍵のファイル、アカウントIDの一致、署名の検証、改ざん・取り違えの拒否） |
| CDK | 10 件（受付用の S3 の CORS と 90 日、Cognito のユーザーの削除の権限、CSP に受付用の S3） |
| 開発用への配備 | 2026-10-04。既存のリソースの変更・置き換えなし（受付用の S3 の追加と画面のファイルの入れ替え） |
| 本物の S3 での確認 | 署名付き POST で、正しいファイルは 204、2MB／100KB を超えるものは 400、種類が違うものは 403、画面の送り元からの CORS の事前確認は 200 |
| 未確認 | 画面から登録・鍵の作成・申請をすること（メールの確認と MFA があるため、開発者が確かめる） |

## 未決事項・リスク

| No. | 内容 | 対応 |
|---|---|---|
| 1 | 届いたパッケージを処理するものがまだない（申請は「アップロード待ち」のまま） | 3b の機械審査の Lambda（S3 のイベント） |
| 2 | 配信元の操作の経緯（`/api/publisher/history`） | 3c（審査の結果を含めて） |
| 3 | 新しく登録した人は、確認のあとに `publisher` グループに入る。最初のログインのトークンにグループが入っていない場合は、ログインし直しが要る | 画面で「ログインし直してください」と案内している。開発者の確認で様子を見る |
| 4 | WebCrypto の Ed25519 は、主なブラウザの最新版でしか使えない | 使えないブラウザでは画面で知らせる |
