## 目的・背景

[DES-004](DES-004-machine-review.md)（3b）で機械審査に合格した申請を、運用者が中身と AI の見本を見て判定し、承認したものを公開のリストに載せる（ADR-001 A-11・A-12、審査基準）。

## 対応元ID（トレーサビリティ）

| 対応元ID | 内容 | 対応状況 |
|---|---|---|
| ADR-001 | A-11（審査）、A-12（承認したものだけを公開）、D-4（AI の見本は運用者のキーでブラウザから） | 実装 |
| API-001 | 審査待ちの一覧、パッケージの取得、見本用のプロンプト、見本の保存、審査の開始・中断、承認・差し戻し・却下 | 実装 |
| DM-001 | 申請の `awaiting_review` ⇄ `in_review` → `approved`/`returned`/`rejected`、REVIEW、`reviews/`、CH の `latestApproved`、`superseded` | 実装 |
| 審査基準（草案） | 項目 1・2.1〜2.7 の指摘、2.7（2 つ以上の AI で見本を作る） | 実装 |

## 方針・決定事項

| No. | 判断 | 理由 |
|---|---|---|
| J-1 | 審査の見本は、運用者のブラウザから AI を直接呼ぶ。対応するのは OpenAI と DeepSeek（どちらも chat completions の形）。返答の長さの指定は OpenAI が `max_completion_tokens`、DeepSeek が `max_tokens` | ADR-001 D-4。審査基準 2.7 は 2 つ以上の AI を求める |
| J-2 | AI の API キーはページのメモリにだけ置き、サービスごとに分けて持つ。保存せず、管理システムのサーバーには送らない | 開発者の決定（2026-10-04） |
| J-3 | CSP の `connect-src` に `https://api.openai.com` と `https://api.deepseek.com` だけを足す | 他へは送れないようにする |
| J-4 | 見本用のプロンプトは機械審査が置いた `samples/{申請ID}/prompts.json` を使う（アプリと同じ station-format で組み立てたもの） | 審査とアプリの話し方をずらさない |
| J-5 | 作った見本は記録用の S3 の `reviews/{申請ID}/{見本ID}.json` に保存し（1MB まで、キーは含めない）、判定のときに見本 ID を添える | 後から判定の根拠を見られる |
| J-6 | 審査の開始と中断は `awaiting_review` ⇄ `in_review`（`If-Match`）。判定は `in_review` のときだけ | 2 人の運用者が同時に判定しない |
| J-7 | 承認: パッケージを読み直して SHA-256 を確かめ、`channel.json` から名前・説明・言語を取り、公開用の S3 に `pkg/{SHA-256}.zip`・`icons/{SHA-256}.png`（変わらないので `immutable`）を置く。1 つのトランザクションで、申請を `approved`、チャンネルに `latestApproved` を記録してリスト（`LISTED`）に入れ、前に承認した申請を `superseded` にし、REVIEW と操作の記録を残す。そのあと公開を頼み、アップロードしたファイルを `archive/` に移す | 確かめたものだけを載せる。DM-001 |
| J-8 | 差し戻し・却下は、審査基準の項目番号（`^[0-9]+(\.[0-9]+)*$`）付きの指摘を 1 つ以上必須にし、チャンネルを空け、ファイルを `archive/` に移す。配信元の画面に理由を出す | 配信元が直せるように |
| J-9 | 結果のメールは 3d（SES） | ADR-001 A-19 |

## 検証結果

| 項目 | 結果 |
|---|---|
| 審査の API のテスト | 7 件合格。審査待ちの一覧、開始・中断、承認から公開（DynamoStore で公開の処理を通し、リストに載ることまで）、差し戻し・却下の指摘必須、運用者だけ |
| 画面のテスト | AI 3 件（サービスごとの宛先・キー・長さの指定、chat モデルだけを出す、どのサービスがなぜ断ったか） |
| CDK | 12 件（CSP に 2 つの AI だけ、`reviews/` の読み書き、`pkg/`・`icons/` への書き込み） |
| DeepSeek の CORS | 管理システムの URL からのプリフライトに 200、`Access-Control-Allow-Origin` が返ることを確認 |
| 本物の AWS での通しの確認（`tools/e2e/review.ts`） | 画面と同じ処理で署名したパッケージが機械審査に合格して審査待ちの一覧に入り、運用者が見本用のプロンプト（6 場面）を取得・見本を保存・審査を開始・承認すると、公開のリストに載った。準拠テストは V-07（パッケージとアイコンの SHA-256・大きさ）を含めて全て合格。後片付けのあと公開し直し、リストが 0 件に戻ることも確認した |
