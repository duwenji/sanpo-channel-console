## 段階記録

### Phase 1（段階1〜6）

- 実施内容: DM-001 の AP-01〜AP-22 と状態の移り方、ADR-001 A-3〜A-18 から操作を洗い出した。SanpoGuide の API-001（RFC 9457・OpenAPI 3.1）の書式を確認した
- 気づいた点: 審査の見本に使うプロンプトの組み立て（PromptTemplates）は station-format ではなくアプリ本体にある。また、配信元の鍵は 1 つなので、鍵の移し替えはチャンネルごとより配信元ごとが自然（DM-001 の改訂が要る）
- 承認ステータス: 完了

### Phase 2（段階7〜8）

- 段階7: 開発者が C-1（PromptTemplates を station-format に移す）、C-2（RFC 9457 + code）、C-3（契約書 + OpenAPI 3.1）、C-4（配信元が自分で退会できる）を決めた
- 段階8: 契約書（console-api.md）と OpenAPI（api/console.openapi.yaml、48 操作）を作成した。Redocly で検証し有効（警告はライセンスの記載と、エラーを default の応答で表していることだけ）。契約書と OpenAPI の操作・エラーコードの一致を確かめた。DM-001 1.1 の改訂案（7 項目）を契約書に記載した
- 承認ステータス: 段階9（開発者のレビュー）待ち

### 段階9（開発者のレビュー、途中）

- 開発者が未決事項 No.2 を決めた: 判定・取り下げ・鍵の移し替えの結果を、Amazon SES でメールする。契約書を 0.2 にし C-14・CV-13・DM-001 への影響 No.8 を追加。構成への追加（SQS・SES・送信ドメインの設定）は ADR-001 の 1.1 の改訂案（A-19・T-8）にした
- 承認ステータス: C-5〜C-14、DM-001 1.1 の改訂案、ADR-001 1.1 の承認待ち

### Phase 3〜4（段階11〜14）

- 段階11・13: 開発者が C-5〜C-14、確認観点 CV-01〜CV-13、DM-001 1.1 の改訂（8 項目）、ADR-001 1.1（A-19・T-8）を承認した。契約書と OpenAPI を 1.0 にした
- 段階14: 次は SanpoGuide 側で PromptTemplates を station-format に移す作業と、station-format の公開方法（ADR-001 T-4）
- 承認ステータス: 完了
