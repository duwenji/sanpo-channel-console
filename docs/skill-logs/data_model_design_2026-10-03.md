## 段階記録

### Phase 1（段階1〜6）

- 実施内容: ADR-001（A-4〜A-18）、SanpoGuide の API-002（リストの項目・`revoked`・P-8・P-9）、API-003（`id`・`version`・エラーコード）、審査基準（判定・取り下げ）から、データの種類と状態の移り方、アクセスパターン AP-01〜AP-22 を整理した
- 気づいた点: 版の番号は配信元がパッケージに書いて署名するので、差し戻し後は同じ番号で出し直される。申請は申請ID（ULID）で区別し、版の番号は「最後に承認した版より大きい」ことだけを確かめる（M-5）
- 承認ステータス: 完了

### Phase 2（段階7〜8）

- 段階7: 開発者が M-1（1 ユーザー = 1 配信元）、M-2（上限: チャンネル 5、審査待ち 1/チャンネル、申請 20/日、試用チケット 10/日）、M-3（操作の記録は同じテーブルに期限なし）、M-4（承認されなかったパッケージは 90 日）を決めた
- 段階8: DM-001 の草案を作成した（M-5〜M-13 は提案、検証観点 DV-01〜DV-13）
- 承認ステータス: 完了

### Phase 3〜4（段階9〜14）

- 段階9・11・13: 開発者が M-5〜M-13 と検証観点を承認した。`revoked` に載せる期間は 90 日の案を 7 日に変えた（7 日を過ぎて取得した端末も、リストにないチャンネルは使わないので安全上の差はない）。取り下げたチャンネルも上限に数える
- 段階14: 次は管理システムの API の契約書（ADR-001 T-3）
- 承認ステータス: 完了
